# FS — веб-оболочка, превью, layout-валидатор, инфраструктура
Твои папки: `api/`, `web/`, `Dockerfile`, `docker-compose.yml`, `validator/layout_*.py`, `scripts/render_preview.py`.
Читаешь: `CLAUDE.md`, `contracts.py`, `pipeline.py` (событие `Progress`). Пока ядра нет — работай на заглушках: `run()` из pipeline принимает `Modules` с любыми реализациями Protocol.

## Задачи
**FS-1. Каркас и запуск.** `Dockerfile` (python:3.11-slim + `libreoffice-impress` + `fonts-liberation`), `docker-compose.yml`, `docker compose up` → UI на :8000; та же сборка ставится на Astra Linux без Docker (`docs/RUN_ASTRA.md`: apt-пакеты, venv, `.env`). CI (GitHub Actions) гоняет `pytest`.

**FS-2. API (api/).** FastAPI: `POST /api/jobs` (multipart: `text` или файл .txt/.md/.csv, `template` — файл или `default`/`interrao`/`example`, `model` — необязательный override) → `job_id`; `GET /api/jobs/{id}/events` — **SSE** со стадиями из `pipeline.Progress` (`profile, ingest, plan, fit, render, validate, report`) + пояснение «Попытка N» при repair; `GET /api/jobs/{id}/result.pptx`, `/report.json`, `/plan.json`, `/preview/{n}.png`. Задачи в фоне, состояние на диске `out/jobs/<id>/`. Все вызовы ядра — только через `pipeline.run`.

**FS-3. Превью (scripts/render_preview.py).** `soffice --headless --convert-to pdf` → `pdftoppm -r 80 -png` → `out/jobs/<id>/preview/*.png`. Функция `render_preview(pptx)->list[Path]`, таймаут и понятная ошибка, если LibreOffice недоступен (UI тогда показывает только скачивание).

**FS-4. Layout-валидатор (validator/layout_*.py).** Часть реализации `Validator`: (a) оценка переполнения по текстовым метрикам: для каждой фигуры из PPTX считаем высоту текста при кегле и ширине (Pillow + Liberation Sans) и сравниваем с bbox → `TEXT_OVERFLOW`; (b) проверка по растру: рендер слайдов (FS-3), поиск закрашенных пикселей текста за границами рабочей зоны/вне слайда → `TEXT_OVERFLOW`; (c) структурные проверки: `EMPTY_PLACEHOLDER`, `AUTOFIT_USED`, `FONT_NOT_ALLOWED` (любой шрифт кроме Liberation Sans/шрифтов шаблона), `PPTX_INVALID` (python-pptx открывает, rels целы). Возвращает `list[Issue]`; fidelity-проверки делает BA/ML1 в `fidelity.py`, сведение — класс `CompositeValidator` в `validator/__init__.py` (твой).

**FS-5. UI (web/).** Одна страница, без сложной сборки (HTML + немного JS/HTMX или Vite+React — на твой выбор, но `docker compose up` должен всё собирать): поле текста + загрузка файла, выбор шаблона (по умолчанию ИнтерРАО, можно загрузить свой .pptx), селект модели, кнопка «Сгенерировать»; ниже **живая лента стадий** (демо «процесс генерации»), затем карусель превью слайдов, кнопки «Скачать PPTX», «Отчёт проверки» (метрики fidelity, список замечаний), выпадающий «План слайдов (JSON)». Для демонстрации исходного содержания — рядом исходный текст.

**FS-6. Р7-Офис.** Поставить Р7-Офис (десктоп для Linux) на ВМ Astra/в виртуальный стенд, открыть и отредактировать каждый выходной файл золотого набора, заполнить `docs/R7_COMPAT_CHECKLIST.md` совместно с BA: открывается, шрифты, таблицы редактируются, нет предупреждений о восстановлении. **Сделать в первые дни, не перед сдачей.** Баги совместимости — ML2 (рендер).
