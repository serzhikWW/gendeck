# ML1 — LLM-слой, планировщик, пайплайн (владелец ядра)
Твои папки: `llm/`, `planner/`, `pipeline.py`, `cli.py`, `docs/PROMPTS.md`, `scripts/eval_models.py`.
Читаешь: `CLAUDE.md`, `contracts.py`. Зависишь от: BA (ingest, золотые данные), ML2 (catalog/fitter/renderer). Работай на моках, пока их нет.

## Задачи
**ML1-1. `LLMClient` (llm/base.py).** OpenAI-совместимый `POST {base_url}/chat/completions` через httpx. Режимы `LLM_STRUCTURED_MODE`: `json_schema` (response_format с JSON-схемой pydantic) → `json_object` → `prompt_only` (схема в промпте, вырезание JSON из ответа). Валидация pydantic; при ошибке — repair-повтор с текстом ошибки (до 2 раз); ретраи сети с backoff; логирование запрос/ответ/токены/латентность в `out/llm_log.jsonl`. Для gpt-oss отключай/ограничивай reasoning, если провайдер это поддерживает (параметр в конфиге). Тест: фейковый HTTP-сервер, невалидный JSON → repair → успех.
*Готово, когда:* смена `LLM_MODEL/BASE_URL` в `.env` не требует правок кода; тесты на 3 режима зелёные.

**ML1-2. Промпт планировщика (planner/).** `Planner.plan(src, catalog, feedback)->DeckPlan`. В промпт входят: правила («не выдумывай факты и числа; таблицы только ссылкой `source_id`; число из прозы — с `evidence.quote` дословно; один смысл на слайд»), **каталог типов слайдов с лимитами** (из `TemplateCatalog`: макс. буллетов, макс. символов в буллете/заголовке, есть ли таблица), секции источника и список таблиц (id, колонки, число строк — без ячеек). Системный промпт и few-shot (2 примера из `data/gold/`) лежат в `docs/PROMPTS.md` и версионируются. Вход длинный → map-reduce: сначала outline по секциям, затем слайды на секцию (отдельный вызов), чтобы не терять контекст.
*Готово, когда:* на 6 образцах BA план проходит pydantic с первого-второго раза, ≥95% слайдов укладываются в лимиты каталога без Fitter-сокращений.

**ML1-3. Repair-цикл и деградация (pipeline.py уже содержит каркас).** Переводи `Issue` валидатора в текстовый feedback планировщику (какой слайд, что не так: «число 12,4 не найдено в источнике», «заголовок 140 симв., лимит 70»). Если после MAX_REPAIRS остались errors — Fitter получает план как есть, в отчёт идёт warning, файл всё равно создаётся. Отдельный fallback `plan_without_llm(src)` (секции → слайды, таблицы → table-слайды) на случай недоступности API.
*Готово, когда:* при выключенной сети `cli` всё равно создаёт PPTX из fallback-плана.

**ML1-4. CLI.** `python -m deckgen.cli --input X --template T -o OUT [--demo] [--no-llm]` на typer; печатает стадии (те же события, что `Progress`) и итоговый отчёт; сохраняет рядом `*.report.json` и `*.plan.json`. `--demo` — готовый пример из `data/samples/01_*`.

**ML1-5. Оценка моделей (`scripts/eval_models.py`).** Прогон золотого набора BA через заданные модели (gpt-oss-120b, Qwen3.6 35B-A3B, позже Yandex): метрики из `ValidationReport.metrics` + доля repair-итераций + время + токены → `docs/MODEL_COMPARISON.md`. Это материал для описания «замена модели без переработки».

**ML1-6. Дружба с Yandex к финалу.** Проверь, что YandexGPT/Alice через OpenAI-совместимый эндпоинт работает с тем же клиентом; отметь различия (structured output, лимиты контекста) в `docs/PROMPTS.md`.
