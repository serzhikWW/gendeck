Твои папки: `template/`, `fitter/`, `renderer/`, `templates/profiles/`.
Читаешь: `CLAUDE.md`, `contracts.py`, `docs/TEMPLATE_README_from_organizers.md`. Эталонные шаблоны в `templates/`.
Если тебя оттянут на другие задачи, FS забирает ML2-4/ML2-5 — поэтому пиши так, чтобы код читался без тебя, и держи `docs/ENGINE_NOTES.md`.

## Факты о шаблонах (проверены инспекцией)
- `example_fields.pptx` (12192000×6858000): макеты `title1, section1, slide1, slide2, table_text1, table_only1, last1`; поля `TITLE_FIELD (idx0)`, `TEXT_FIELD (idx1)`, `TABLE_FIELD (idx2, тип TABLE)`, `IMAGE_FIELD (idx13, PICTURE)`; слайд-образец в файле — один.
- `interrao_corporate.pptx` (13430250×7561263): макеты `1_Титульный слайд, 3_Титульный слайд, 1_Заголовок раздела, 1_Заголовок и объект, 2_Заголовок раздела, 2_Титульный слайд`; в макетах только Title. Образцы: слайд 1 (титул, тексты — TextBox), слайд 2 (раздел), слайд 3 (пустой контентный — основа для `slide`/`table`), слайды 8/9 (стиль таблиц), слайд 28 (финальный «Спасибо»). Стиль из слайда 6: Liberation Sans, заголовок Bold 14/16 caps оранжевый, основной 12/11pt, буллеты, примечание 10pt.

## Задачи
**ML2-1. Profiler: ConventionAdapter (template/).** `profile(path)->TemplateCatalog`: перебор макетов, тип слайда по префиксу имени (`title*/section*/slide*/table*/last*`), поля по именам фигур `*_FIELD`, `bbox`, кегль (из layout/master XML), оценка `max_chars/max_lines` по метрикам Liberation Sans (Pillow ImageFont по ttf; ёмкость = f(ширина, высота, кегль, межстрочный)). Шаблон не найден/другие имена → понятное исключение. Тесты на `example_fields.pptx`.

**ML2-2. Profiler: ProfileAdapter + `templates/profiles/interrao.yaml`.** YAML описывает для каждого `SlideType`: `source: sample_slide`, `sample_slide_index`, зоны (`TITLE`, `TEXT`, `TABLE` в EMU, снять с реальных слайдов), `StyleTokens` (шрифт, кегли, цвета заголовка/шапки таблицы). Автовыбор адаптера: есть README-макеты → convention, иначе ищем `<имя шаблона>.yaml` / `profiles/`.
*Готово, когда:* оба шаблона дают валидный `TemplateCatalog`, тест `test_catalogs.py`.

**ML2-3. Fitter (fitter/).** `fit(plan, src, catalog)->FittedDeck`: (a) подстановка ячеек таблиц из `SourceTable` по `source_id` (строки без изменений); (b) выбор `layout_id` по типу слайда и наполнению (текст+таблица → `table_text*`, только таблица → `table_only*`, нет таблицы → `slide1`; для ИнтерРАО — sample_slide); (c) проверка ёмкости: слишком много буллетов/длинный текст → снижение кегля в пределах `StyleTokens.min`, иначе **разбиение слайда** («…(1/2)»); большие таблицы режутся по строкам с повтором шапки, ширина колонок по содержимому; (d) убрать дубли пустых слайдов. Чистая функция, детерминированно, покрыта тестами.

**ML2-4. Renderer (renderer/).** `render(deck, template_path, catalog, out_path)`: открыть шаблон, **клонировать нужный макет/слайд-образец**, залить поля, вставить таблицу (`placeholder.insert_table` для convention; свой `graphicFrame` по зоне для profile), явные кегли и шрифт Liberation Sans, `notes` в заметки, удалить слайды-образцы из шаблона и пустые плейсхолдеры, отключить autofit. Итог — валидный PPTX без служебного мусора.
*Готово, когда:* золотые планы BA (`data/gold/*.plan.json`) без LLM превращаются в PPTX, открываемые в LibreOffice без предупреждений.

**ML2-5. Таблицы высокого качества.** Стиль шапки/зебры из шаблона, выравнивание чисел вправо, текст влево, объединённые ячейки не использовать (совместимость с Р7), максимум читаемый кегль, перенос по словам. Тест: таблица 12×6 и 30×8 корректно режется.

**ML2-6. Совместимость с Р7.** Совместно с FS/BA: чек-лист (`docs/R7_COMPAT_CHECKLIST.md`), проверка XML выходного файла (нет autofit, нет битых rels, нет неиспользуемых media), регрессионный тест `test_pptx_sanity.py`.
