# ENGINE_NOTES — движок шаблонов (ML2)

Как устроены `template/`, `fitter/`, `renderer/` — чтобы код можно было вести без автора (FS забирает ML2-4/5, если ML2 отвлекут).

## Точки входа (реализации Protocol из contracts.py)
```python
from deckgen.template import TemplateProfilerImpl   # .profile(path) -> TemplateCatalog
from deckgen.fitter import DeterministicFitter      # .fit(plan, src, catalog) -> FittedDeck
from deckgen.renderer import PptxRenderer           # .render(deck, template_path, catalog, out_path)
```
Всё детерминировано, LLM не вызывается, `llm/` не импортируется.

## Profiler (`template/`)
- **Автовыбор адаптера** (`template/__init__.py`): есть макет с именем `title*/section*/slide*/table*/last*` (регистр не важен) и фигурой `TITLE_FIELD` → `convention`; иначе ищем YAML-профиль → `profile`; иначе `TemplateError` с понятным текстом (есть список найденных макетов).
- **convention** (`convention.py`): поле = фигура макета, в имени которой есть `TITLE|SUBTITLE|TEXT|TABLE|IMAGE_FIELD`. Повторы получают суффикс `#2`. Кегль: `lstStyle` плейсхолдера → плейсхолдер мастера → `txStyles` мастера (`ooxml.py`). `layout_id` = имя макета (дубли имён → `имя#2`).
  - В `example_fields.pptx` у title1/section1 **нет `SUBTITLE_FIELD`**, поэтому подзаголовок синтезируется: поле `SUBTITLE_FIELD` с `placeholder_idx=None` в свободной полосе под заголовком (до ближайшей декоративной фигуры), рендерер ставит туда TextBox с выравниванием заголовка.
  - В макетах таблиц лежит скрытая (за краем слайда) таблица `STYLE_TABLE` — её `tableStyleId` рендерер берёт для наших таблиц.
  - В макетах есть `normAutofit` — рендерер заменяет его на `noAutofit` и в слайдах, и в макетах/мастере выходного файла.
- **profile** (`profile.py`, `templates/profiles/*.yaml`): поиск профиля — `<шаблон>.yaml` рядом с шаблоном → `$DECKGEN_PROFILES_DIR`, `<папка шаблона>/profiles`, `templates/profiles` по `template:` (имя файла) или `match:` (размер слайда + имена макетов; так находится загруженный через UI файл с любым именем). В YAML `sample_slide` — 1-based (как в PowerPoint), в каталоге `sample_slide_index` — 0-based.
- **Ёмкость** (`metrics.py`): `max_lines` = высота/(кегль·1.15·lnSpc), `max_chars` = символов в строке × строк × 0.85. Ширины берутся из TTF через Pillow: `$DECKGEN_FONT_PATH` → системный Liberation Sans → Arial (метрически совместим с Liberation Sans) → эвристика 0.55 em. Запас ширины 6% (`WIDTH_SAFETY`) под разницу переносов LibreOffice/Р7.

### ИнтерРАО (`templates/profiles/interrao.yaml`)
| тип | образец | поля |
|---|---|---|
| title | слайд 1 | TITLE → `TextBox 1` (40pt, 003D80), SUBTITLE → `TextBox 2` (16pt) — обе растянуты на ширину полосы под логотипом |
| section | слайд 2 | TITLE = плейсхолдер idx0 на голубой полосе (32pt, белый из макета) |
| slide | слайд 3 | TITLE idx0 (24pt), TEXT — зона между линиями (548457, 884890, 12219181×6150000) |
| table (текст+таблица) | слайд 3 | TEXT слева 4,2 млн EMU, TABLE справа |
| table (только таблица) | слайд 3 | TABLE на всю зону |
| last | слайд 28 | без полей: «СПАСИБО ЗА ВНИМАНИЕ!» зашито в макет `2_Заголовок раздела` |

Стиль таблиц — как на образцах 8/9: шапка оранжевая жирная (F18400) на F2F2F2, только горизонтальные линии D9D9D9, без вертикалей; стиль таблицы `No Style, No Grid`. Номер слайда и «ПРЕЗЕНТАЦИЯ О КОМПАНИИ» приходят из макета.

## Fitter (`fitter/`)
1. Таблица по `source_id` **целиком заменяется** ячейками `SourceTable` (то, что написал LLM, игнорируется). `header_rows = 1`, если есть `columns`. Ссылка в никуда без ячеек → таблицы нет, слайд становится обычным.
2. slide↔table по факту наличия таблицы; контентный слайд без текста и таблицы → `section`; без заголовка и содержимого → выкидывается. Маркеры `•`, `-`, `1.` в начале буллетов срезаются.
3. Макет выбирается по скорингу (`_pick_content`): нужен TEXT / TABLE, штраф за лишнее TABLE, за неиспользуемое TEXT, за IMAGE. Так работает и с незнакомыми именами макетов (`table2`, `slide_wide`). Нет титульного/финального макета → фолбэк section → title → slide.
4. Ёмкость (`measure.py`, те же функции зовёт рендерер):
   - текст: кегль от `body_pt_max` вниз шагом 0.5 до `body_pt_min`; не влезло или > 8 буллетов (`MAX_BULLETS_PER_SLIDE`) → деление на k сбалансированных частей «… (1/2)», общий кегль. Сверхдлинный буллет режется по предложениям. **Текст не обрезается и не переписывается.**
   - таблица: кегль `table_pt_max`→`table_pt_min`, ширины колонок по содержимому (минимум — самое длинное слово), высоты строк по переносам. Не влезло → нарезка по строкам с повтором шапки, кегль ≤ 11pt, части равного размера.
   - текст+таблица не влезают вместе → отдельный слайд текста + слайд(ы) таблицы.
5. Подряд идущие одинаковые слайды схлопываются.
- Зоны (`template/geometry.py`): неиспользуемые поля в той же горизонтальной полосе отдаются соседу — в `table_only1` таблица занимает и место `IMAGE_FIELD`, в `table_text1` без текста — и место `TEXT_FIELD`.
- `FittedSlide.font_pt`: ключ = имя поля макета (`TITLE_FIELD`, `TEXT`, ...).

## Renderer (`renderer/`)
- convention: `add_slide(макет)` → плейсхолдеры по idx; таблица — `insert_table` в `TABLE_FIELD` (нативный `graphicFrame` + `a:tbl`), позиция/размер — по зоне.
- profile: клон слайда-образца (`ops.clone_slide`: фигуры + фон + rels на картинки; диаграммы/OLE не копируются), поля — фигуры по имени из YAML или новые TextBox; таблица — `add_table` в зоне.
- Каждый ран: явный `sz`, `latin/ea/cs = Liberation Sans`. Буллеты: `•` с цветом из шаблона (`buClr` текстового плейсхолдера / `colors.accent` профиля), lnSpc 90%, отступ перед абзацем 0.45 кегля (`template/textstyle.py` — меняется в одном месте для расчёта и рендера).
- Числовые колонки (≥60% ячеек — числа, `≥ 10`, `—`, `~23*`) выравниваются вправо, текст — влево. Объединённых ячеек нет.
- Финал: удаляются исходные слайды шаблона, пустые плейсхолдеры (вкл. `IMAGE_FIELD`), autofit во всём пакете; части перенумеровываются `slide1..N.xml`; неиспользуемые media не попадают в файл (python-pptx пишет только достижимые части). `notes` → заметки слайда.

## Известные ограничения
- Поле `*_FIELD`, которое в макете не плейсхолдер, а обычная фигура, заполнить нельзя (оно статично на всех слайдах) — такие поля игнорируются.
- Два `TEXT_FIELD` на макете (колонки) — используется первое.
- `IMAGE_FIELD` не заполняется (картинок в полуфинале нет), поэтому макеты с картинкой выбираются только в крайнем случае.
- Заголовок не делится: если и при 75% кегля не влезает, остаётся как есть (переполнение ловит валидатор).
- Совместимость с Р7 пока проверена только косвенно (LibreOffice + XML-проверки); ML2-6 — живой прогон в Р7 с FS/BA.
